# md2tex Workshop 0.1.4 beta

This Linux desktop prerelease adds opt-in failed-build explanations, evidence-bound finding cards, copying of current advice and verified Markdown source navigation. Suggested corrections remain manual. It excludes the later chat, project-import, reviewed-edit and AI connection-manager chain.

## Install through BRAT

1. In a disposable Linux desktop vault, install and enable BRAT 1.1.0 or newer.
2. Run **Add a beta plugin for testing**, enter `pafloxy/obsidian-md2tex-workshop` and choose frozen version **0.1.4**.
3. Enable **md2tex Workshop**. Configure an absolute Node.js 24+ executable if the desktop GUI PATH does not find it.
4. Supply the external `latexmk`, selected TeX engine and packages required by your document recipe; the default bibliography recipe uses BibTeX. The plugin does not install these tools.
5. Copy the quickstart note into the disposable vault. Build, inspect the PDF/log, and review guarded linked-TeX recovery before using existing notes. Preserve backups and linked-target state.

The release attaches exactly `main.js`, `manifest.json` and `styles.css`. The runtime and license notices are embedded; first load restores and verifies companion bytes inside the plugin directory without downloading additional runtime code. Old or interrupted runtime directories are preserved rather than automatically repaired or deleted.

## Assistance and data boundaries

Assistance is off until explicitly enabled. The Local API route sends bounded captured source/log evidence to a configured loopback HTTP server, which may forward it to a remote model. Codex uses the selected installed CLI and may use saved authentication, contact a cloud provider and incur charges. Its read-only invocation is not proof of operating-system confinement. Ordinary builds do not need a provider account or model call. This feature accepts no API key for the local HTTP route.

Advice is inert text. Source/job freshness is checked before presenting, copying or navigating findings; changed or conflicting notes refuse stale operations. There is no agent Apply action in this release. Review suggestions, edit manually and rebuild. A validated explanation is not proof that its advice is correct.

Explicit CLI recipes and linked targets can access configured files outside a vault. Build attempts, logs, previews, backups and owned linked-target state are retained at configured output locations. TeX dependencies and trusted local agents do not constitute a general filesystem sandbox.

## Verification and limits

The exact candidate source previously completed **249 passing full-suite tests, zero failures and one optional biblatex/Biber skip**, plus 63 passing fast tests, source export/verification, toolchain doctor, a real quickstart PDF and deterministic packaging. The version-pinned release workflow repeats fast/full checks on this release source, builds a separate verified export, requires the reviewed asset hashes and downloads draft assets for exact comparison before publishing.

**Fresh native Obsidian and hosted BRAT installation acceptance for these exact bytes remain unverified.** Automated host doubles and synthetic provider fixtures do not establish native GUI behavior or real-provider quality. Historical native rehearsals described elsewhere are not acceptance of this release. Test installation/enable/reload, native PDF/log, guarded recovery and stale advice/navigation in a disposable vault.

This is Linux desktop only. The worker requires Linux process groups; macOS, Windows and mobile execution are unsupported. The declared minimum Obsidian version is 1.7.2 and has not been natively validated. The optional Biber integration is not enabled in the publication workflow. Community-directory submission and its policy review remain separate work.
